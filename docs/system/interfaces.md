### 2.11 API routes — **IMPLEMENTED**

- **Ответственность:** HTTP-граница между Web UI (и потенциально внешними интеграциями) и доменными сервисами.
- **Файлы:**
  - Существующие: `src/app/api/video-metadata/{apply,preview,transcript}/route.ts`, `src/app/api/youtube/{videos,playlists,create-playlist,add-to-playlist,remove-from-playlist,channel-info}/route.ts`, `src/app/api/auth/[...nextauth]/route.ts`. (`src/app/api/rules/route.ts` и `src/app/api/run/route.ts` — вместе с самой Rules-фичей — удалены 2026-09-20.)
  - **Новые (Phase 2):** `GET /api/channels` (`route.ts`), `POST /api/channels/sync` (`sync/route.ts`), `GET /api/channels/[channelId]/videos` (`[channelId]/videos/route.ts`).
  - **Новые (Phase 3):** `GET /api/channels/[channelId]/localizations` (обзорная таблица), `GET /api/channels/[channelId]/localizations/[videoId]` (детали видео), `GET /api/channels/[channelId]/localizations/export` (XLSX-файл, `?videoIds=a,b,c` опционально).
  - **Новые (Phase 4):** `POST /api/channels/[channelId]/localizations/import/preview` (multipart, без персистентности), `POST /api/channels/[channelId]/localizations/import` (multipart, создаёт Change Set), `GET /api/channels/[channelId]/change-sets` (список), `GET /api/channels/[channelId]/change-sets/[changeSetId]` (детали + ревалидация конфликтов, фильтры/пагинация), `POST .../change-sets/[changeSetId]/changes/[changeId]/approve`, `POST .../changes/[changeId]/reject`, `POST .../change-sets/[changeSetId]/approve-all`, `POST .../change-sets/[changeSetId]/reject-all`.
  - **Новые (Phase 5 completion task, 2026-09-18):** `GET/POST /api/channels/[channelId]/batches` (список/создание — по умолчанию `dryRun: true` принудительно, см. ниже), `GET /api/channels/[channelId]/batches/[batchId]` (batch + ledger rows, channel-scoped через `requireBatchForChannel`), `POST .../batches/[batchId]/prepare` (запуск dry-run пайплайна, `prepareBatchExecution`), `GET .../batches/[batchId]/errors` (`getBatchErrorReport`), `GET .../batches/[batchId]/audit` (`createAuditCore().listForBatch`).
  - **Новые (2026-09-21, BL-045/BL-047 — Gate B + MCP connection toggles, см. §2.9f):** `GET/POST /api/settings` (`liveWritesEnabled`/`mcpConnectionEnabled` флаги), `POST .../batches/[batchId]/execute` — единственный роут, которому разрешено ссылаться на `executeBatch`/`WriteExecutor` (явное, единственное исключение в `write-path-inventory.test.ts`; см. §2.9f). `POST .../batches` теперь честно создаёт `dryRun: false` batch, но только пока настройка live-writes включена в момент вызова — иначе всё ещё принудительно `dryRun: true`, как раньше. **Все остальные роуты этой секции по-прежнему не вызывают и не ссылаются на live-execution функции/типы** — проверено автоматическим тестом `src/lib/batches/write-path-inventory.test.ts`, который ищет эти символы по содержимому файлов (включая комментарии), а не только по импортам.
  - **Новые (Phase 6, Slice 1):** `POST /api/channels/[channelId]/ai-localization/generate` (превью-генерация, ничего не персистит), `POST /api/channels/[channelId]/ai-localization/change-sets` (создаёт Change Set из отредактированных предложений через `changesets.createChangeSetFromProposals`). Оба роута только вызывают `createAiLocalizationCore()` и не содержат отдельной approve/batch-логики — она полностью переиспользуется из уже существующих Change Set/Batches роутов выше.
  - **Новые (Phase 6, Channel Editorial Profiles, 2026-09-19):** `GET/PUT /api/channels/[channelId]/ai-localization/profile` (просмотр/сохранение профиля), `GET /api/channels/[channelId]/ai-localization/change-sets/[changeSetId]/provenance` (read-only, channel-scoped: возвращает `null`, если запись принадлежит другому каналу).
  - **Новые (Phase 6, AI Connections, 2026-09-19):** `GET/POST /api/ai-connections` (список/создание — глобально, не channel-scoped, см. §2.9c), `GET/PUT/DELETE /api/ai-connections/[connectionId]`, `POST /api/ai-connections/[connectionId]/test` (единственный вызывающий `testConnection`, всегда явное действие пользователя).
  - **Новые (Cloud connection, 2026-09-22, см. §2.9j, не в `dev`):** `GET /api/cloud-connection/start` (редирект на Google consent, `state` в httpOnly cookie), `GET /api/cloud-connection/callback` (обмен кода на токены, редирект обратно на дашборд), `GET /api/cloud-connection/status` (публичный статус, без токена), `POST /api/cloud-connection/disconnect`. Полностью независимы от `[...nextauth]` — отдельный OAuth-флоу, не завязанный на активный канал.
- **Точки входа:** HTTP-запросы, каждый начинается с `getServerSession(authOptions)`.
- **Зависимости:** соответствующий доменный core (`createVideoMetadataCore()`, `createPlaylistManagementCore()`, `createChannelSyncCore()`, `createLocalizationCore()`, `createChangeSetCore()`, `createBatchCore()`, `createAuditCore()`), общие `error-status.ts`/`parse-json-body.ts` из `video-metadata` (переиспользуются, не дублируются).
- **Read/Write:** зависит от роута; все новые роуты Phase 2–5 не пишут в YouTube (export/import/approve/batches — либо чтение, либо только локальная запись в БД; batches-роуты структурно не могут достичь `videos.update`).
- **Важные ограничения безопасности:** без валидной сессии — `401` до вызова доменной логики; каждый change-set/batch роут проверяет, что вложенный ресурс принадлежит указанному `channelId` (`not_found`/`batch_not_found` иначе), чтобы нельзя было прочитать/изменить чужой ресурс через чужой канал.

### 2.12 CLI — **IMPLEMENTED** (metadata/auth/playlist/changeset/batch/channel/analytics/ai-localization); только apply-класс (approve/execute) для Change Sets/Batches остаётся **PLANNED** (см. `docs/TECHNICAL_DEBT.md` RISK-04, PARTIALLY RESOLVED)

- **Ответственность:** локальный терминальный интерфейс для metadata/auth/playlist/changeset/batch/channel/analytics операций.
- **Файлы:** `src/cli/video-metadata.ts` (namespaces: `metadata` (без явного префикса), `auth`, `playlist`, `changeset`, `batch`, `channel`, `analytics`).
- **Точки входа:** `npm run cli:video-metadata -- <namespace> <command>`.
- **Зависимости:** `createVideoMetadataCore()`, `createPlaylistManagementCore()`, `createCliAuthService()`, `createChangeSetCore()`, `createBatchCore()`, `createChannelSyncCore()`, `createAnalyticsCore()` — те же фабрики, что MCP и Web UI, без параллельной реализации (AGENTS.md §D).
- **Read/Write:** `apply`, `playlist create/update/delete/add/remove`, `channel sync`, `changeset import`, `ai-localization create-change-set` — write (`channel sync`/`changeset import`/`ai-localization create-change-set` пишут только в локальную БД, никогда в YouTube, но всё равно гейтятся); `changeset list/get/preview`, `batch list/get`, `channel list/video-list`, `analytics list/overview/data-quality/comparable-age/weekly-reports/weekly-report-get`, `ai-localization generate` — read-only, не гейтятся (`analytics overview`/`ai-localization generate` с реальным `--connectionId` — живые сетевые вызовы, но по той же логике §6.7 классифицируются как read, не мутация; реальный `--connectionId` гейтится своей собственной внутренней проверкой, RISK-30).
- **Важные ограничения безопасности:** JSON-конверты на stdout (`{ ok: true|false, ... }`), ненулевой exit code при ошибке; `READ_ONLY_CLI_COMMANDS`/`AUTH_SESSION_EXEMPT_CLI_COMMANDS` — единственные два явных списка исключений из гейта, всё остальное гейтится по умолчанию (fail-safe: забыть добавить команду в whitelist делает её излишне гейтированной, а не негейтированной); `--file` читается напрямую с диска (в отличие от MCP, где нет бинарного поля и нужен base64); `batch get` проверяет принадлежность батча каналу через `requireBatchForChannel` (AGENTS.md §F).

### 2.13 MCP — **IMPLEMENTED** (metadata/auth/playlist tools; read/propose/create Change Set tools; read-only Batch tools; channel-sync tools; analytics read tools; AI Localization generate/create-Change-Set tools); только apply-класс (approve/execute) для Change Sets/Batches остаётся **PLANNED** (см. `docs/TECHNICAL_DEBT.md` RISK-04, PARTIALLY RESOLVED)

- **Ответственность:** MCP-сервер для AI-агентов, раздаётся самим приложением по HTTP (`POST /api/mcp`, `src/lib/agent-mcp-endpoint`, stateless, только loopback; ADR 0013). stdio удалён.
- **Файлы:** `src/mcp/server.ts` (`createMcpServer`, `createMcpToolHandlers`).
- **Точки входа:** `POST /api/mcp` (`src/app/api/mcp/route.ts`); инструменты: `write_context`, `write_channel_list`, `write_channel_select`, `whoami`, `auth_user_select`, `list`, `transcript`, `preview`, `apply`, `playlist_list`, `playlist_create`, `playlist_update`, `playlist_delete`, `playlist_add_videos`, `playlist_remove_videos`, `changeset_list`, `changeset_get`, `localization_import_preview`, `batch_list`, `batch_get` (Phase 7 slice 1, `docs/roadmap/plans/PHASE_7_PLAN.md`), `channel_sync`, `channel_list`, `channel_video_list` (`BL-008`, `docs/roadmap/BACKLOG.md`), `changeset_create_from_import` (реальное создание Change Set, не только превью), `analytics_list`, `analytics_overview`, `analytics_data_quality`, `analytics_comparable_age`, `analytics_weekly_reports_list`, `analytics_weekly_report_get` (2026-09-23, докладка Phase 8 -- "machine-readable analytics for operational agents" / "data-quality diagnostics" / "comparing videos at comparable ages" / "analytical reports and weekly channel reviews", `docs/roadmap/FUTURE_PHASES.md` §4, `docs/ARCHITECTURE.md` §14.9/§14.10/§14.11), `ai_localization_generate`, `ai_localization_create_change_set` (2026-09-23, BL-075/BL-078, см. §2.9b).
- **Зависимости:** те же core-фабрики, что и CLI/Web UI (`createChangeSetCore()`, `createBatchCore()`, `createChannelSyncCore()`, `createAnalyticsCore()` — те же, что использует API этих доменов, без параллельной реализации, AGENTS.md §D); `resolveEffectiveCredentialRef` из `cli-auth`.
- **Read/Write:** `apply`, `playlist_*`, `channel_sync`, `changeset_create_from_import`, `ai_localization_create_change_set` — write (с `dryRun`-поддержкой для `apply`; `channel_sync`/`changeset_create_from_import`/`ai_localization_create_change_set` пишут только в локальную БД, никогда в YouTube, но всё равно гейтятся `assertMcpDeviceAvailable` как локально-мутирующие); `changeset_list`/`changeset_get`/`localization_import_preview`/`batch_list`/`batch_get`/`channel_list`/`channel_video_list`/`analytics_list`/`analytics_overview`/`analytics_data_quality`/`analytics_comparable_age`/`analytics_weekly_reports_list`/`analytics_weekly_report_get`/`ai_localization_generate` — исключительно read/propose-only, не гейтятся (не мутируют ничего; `analytics_overview` — живой запрос к Analytics API, `ai_localization_generate` с реальным `connectionId` — реальный сетевой вызов к AI-провайдеру, но оба классифицируются как read, т.к. ничего не мутируют локально, см. `docs/DEVELOPMENT_PLAYBOOK.md` §6.7; реальный `connectionId`-вызов гейтится своей собственной внутренней проверкой, RISK-30). Сознательно НЕ добавлены `collectMetrics`/`runAutoCollectionIfStale` — это реальные локальные мутации, расходующие Analytics API квоту; запуск нового сбора остаётся только через Web UI/суточный автотриггер.
- **Важные ограничения безопасности:** все входы — строгие Zod-схемы; все ошибки — структурированный JSON, никогда голый текст; `batch_get` проверяет принадлежность батча каналу через `requireBatchForChannel`, а не голый `getBatch(batchId)` (AGENTS.md §F).
- **MCP connection** (тумблер в Settings, второй аргумент `createMcpServer(core, {connectionEnabled: true})`, см. §2.9f) — по умолчанию выключен: сервер не регистрирует НИ ОДНОГО инструмента из списка выше, пока владелец явно не включит тумблер. Реализует "operation-specific permissions and read-only access to application data" из плана Phase 7 (`docs/roadmap/FUTURE_PHASES.md` §3) в default-deny виде: отсутствие доступа — состояние по умолчанию, а не отдельный «ограниченный» режим.
- **Ограничение: apply-класса для Change Sets/Batches через MCP до сих пор нет.** CLI-паритет для read/propose/create Change Set/Batch/channel-sync/analytics инструментов **уже есть** (`src/cli/video-metadata.ts`, namespaces `changeset`/`batch`/`channel`/`analytics`) — это утверждение исправлено 2026-09-23, было устаревшим (паритет добавлен ещё 2026-09-20, см. `docs/ROADMAP_STATUS.md`'s "Phase 7 — in-repository scope" row, эта строка тогда не была обновлена). Approve/reject/create/execute для Change Set/Batch по-прежнему доступны только через Web UI.
