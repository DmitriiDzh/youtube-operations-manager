### 2.9ai Наличие GPU по дата-центрам RunPod — сейчас и журнал раз в 15 минут (BL-172, FO-REQ-0016, `docs/roadmap/plans/GPU_AVAILABILITY_PLAN.md`; с BL-206 — 15 минут вместо 3 часов) — **IMPLEMENTED, влито в `dev` (`12e632a`)**

- **Сейчас:** `factory_media_get_gpu_availability` (Factory API 1.10.0) → `getGpuAvailability` в ядре медиа: два чтения каталога v2 через медиа-шлюз (`listGpuTypes` с `minCudaVersion`, всегда Secure Cloud; `listDataCenters`), сборка — чистая `buildGpuAvailability` (`src/lib/media-generation/gpu-availability.ts`). По GPU — цена, общий запас, `cudaAvailable`, запас по дата-центрам с `networkVolume` и `s3Api`; `s3Api` — документированный список RunPod (`RUNPOD_S3_DATACENTERS`, `runpod-s3.ts`), не живая проверка.
- **Журнал (v81, `media_gpu_availability_log`; v100, `media_gpu_availability_snapshots`):** таймер в `src/instrumentation.ts` раз в 5 минут вызывает `snapshotGpuAvailabilityIfDue` (`gpu-availability-log.ts`): снимок, если последнему 14 минут (BL-206; до этого — 3 часа, таймер раз в 15 минут); без запроса к RunPod при выключенном шлюзе или без настроек; после сбоя — через 15 минут от начала неудачного тика (до BL-206 — через час); не во время импорта и не в режиме восстановления. Снимок: все GPU от 24 ГБ, Secure Cloud, CUDA из настроек; на GPU строка `*` (всегда) и строка на дата-центр с сетевыми томами только там, где запас не NONE (с v100; отсутствие строки = NONE, старые строки NONE не переписаны), плюс одна строка снимка в `media_gpu_availability_snapshots` (`at`, `rows`, `min_cuda_version`). 90 дней (обе таблицы), только на этом устройстве.
- **По минимуму CUDA (BL-208, `docs/roadmap/plans/GPU_START_FIXES_PLAN.md` §F, схема v102):** тик снимает каждый минимум в ходу — из настроек и из установленных шаблонов (по возрастанию; нет ни одного — один снимок без фильтра); каталог дата-центров — раз за тик, каталог GPU — раз на минимум; «пора» и отступ после сбоя — у каждого минимума свои. Снимки — в новой таблице `media_gpu_availability_cuda_snapshots` с ключом `(at, min_cuda_version)`, `''` = без минимума; v102 копирует туда строки v100, старая `media_gpu_availability_snapshots` остаётся, но не читается и не пишется (ADR 0001, только добавление). Чтения журнала и статистики — под одним минимумом (`minCudaVersion`, по умолчанию из настроек), ответ называет его и минимумы в диапазоне (Factory API 1.28.0).
- **Чтение журнала:** `factory_media_list_gpu_availability_log` — строки (до 5 000) или `summary` (подсчёт в SQL по всем строкам; NONE = снимки GPU − остальные уровни, поэтому старые и новые снимки считаются одинаково).

### 2.9ax Статистика доступности GPU и журнал ожидания сессий (BL-206, FO-REQ-0033, `docs/roadmap/plans/GPU_STATS_PLAN.md`) — **IMPLEMENTED на ветке `feature/fo-req-0033-gpu-stats`, не влито в `dev`**
