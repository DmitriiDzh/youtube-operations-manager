### 2.9c AI Connections (Phase 6, "Provider-Agnostic AI Connections", 2026-09-19) — **IMPLEMENTED for the OpenAI-compatible protocol adapter**

- **Ответственность:** provider-agnostic сущность «connection» (id, display name, adapter type, base URL, model id, опциональный зашифрованный credential, enabled, status, capability metadata, task assignment) — управляется через Settings UI. Ни один конкретный вендор/модель не захардкожены; вместо адаптера на модель — маленький protocol-adapter registry (`mock` и `openai_compatible`).
- **Файлы:** `src/lib/ai-connections/{contracts,schemas,crypto,endpoint-security,services,index}.ts`, `adapters/{registry,mock-adapter,openai-compatible,store}.ts`; тесты: `crypto.test.ts`, `endpoint-security.test.ts`, `services.test.ts`, `adapters/openai-compatible.test.ts`, `integration.acceptance.test.ts`, `write-path-inventory.test.ts` (37 тестов; +2 после независимого security-ревью: redirect-based SSRF bypass, IPv6-фикс). UI: `src/components/ai-connections-manager.tsx` (вкладка «Settings»); интеграция в «Generate with AI» секцию `languages-manager.tsx` (ранее — `ai-localization-panel.tsx`) через выпадающий список connection (по умолчанию — mock, без сети).
- **Хранение credential — архитектурное решение (см. `docs/acceptance/PHASE_6_AI_CONNECTIONS_ACCEPTANCE.md` §2):** НЕ OS-keychain (отложено — нативная зависимость, кроссплатформенный риск), НЕ plaintext (запрещено явно). Выбрано: **AES-256-GCM, ключ из `AI_CONNECTIONS_ENCRYPTION_KEY`** (env-переменная, никогда не в репозитории — base64, 32 байта), шифротекст в отдельной таблице `ai_connection_credentials` (никогда не в одной таблице/запросе с публичными полями connection). Без настроенного ключа сохранение connection с credential падает с `encryption_key_not_configured` — **plaintext-фолбэка нет**.
- **Endpoint security (SSRF):** `endpoint-security.ts`'s `validateEndpointUrl` — HTTPS обязателен для удалённых endpoint'ов; IP-литералы и DNS-резолвленные адреса проверяются против списка приватных/loopback/link-local/metadata (включая `169.254.169.254`)/reserved диапазонов (IPv4 и IPv6); local-inference mode — отдельный, явно включаемый флаг connection, разрешающий localhost/приватную сеть. Проверка выполняется и при сохранении, и непосредственно перед каждым реальным исходящим вызовом (defense-in-depth). **Задокументированное остаточное ограничение:** проверка не «пиннит» сокет к провалидированному адресу — узкое TOCTOU-окно для DNS rebinding остаётся (см. `docs/TECHNICAL_DEBT.md`), приемлемо для текущей модели «доверенный оператор на своей машине» (Gate D).
- **Точки входа:** `GET/POST /api/ai-connections`, `GET/PUT/DELETE /api/ai-connections/[connectionId]`, `POST /api/ai-connections/[connectionId]/test` (единственный способ вызвать `testConnection` — явное действие пользователя, никогда не автоматически); `ai-localization.generateProposals` принимает опциональный `connectionId`, который резолвится в `LocalizationProvider` через `resolveConnectionProvider` — домен `ai-localization` при этом не меняется (только одно новое опциональное поле зависимостей).
- **Read/Write:** реальный сетевой вызов возможен только через `openai_compatible`-адаптер, и только по явному действию (generate с выбранным connection, или Test connection). Ни модуль, ни его тесты никогда не вызывают `fetch` напрямую — только через инжектируемый `fetchImpl` (структурно проверено инвентарным тестом), поэтому «ноль реальных сетевых вызовов в автотестах» — не обещание, а проверяемое свойство.
- **Cost controls:** отдельный, более низкий лимит целей на вызов через реальный connection (50, против гораздо более высокого лимита mock-режима), timeout (по умолчанию 30с) + ограниченный retry (2 попытки) на transient-ошибки, token usage из ответа провайдера (если есть) прокидывается вверх, неизвестное usage/pricing репортится как `null`, никогда как ноль.
- **Важные ограничения безопасности:** ни один код-путь не возвращает сохранённый credential клиенту (`hasCredential: boolean` — единственное публичное поле); каждый новый роут — та же сессионная проверка, что и везде в кодовой базе; capability `"none"` (или необъявленная) — явная ошибка `capability_not_supported` до любого сетевого вызова, никогда не best-effort попытка; вывод реального provider'а валидируется теми же полевыми правилами, что и mock (переиспользуется `classifyAndValidateField`, не дублируется).
- **Чего нет:** OS-keychain; универсального agent-execution фреймворка; Codex как провайдера; выбранного платного вендора/модели.
