### 2.9v Market Intelligence — исследовательский watchlist (Phase 9, слайсы 1-4 + 9A-9E + 9G + 9H (части A-C) + 9I, `docs/roadmap/plans/PHASE_9_PLAN.md`) — **IMPLEMENTED для описанного ниже объёма**

- **Статус:** owner instruction, Telegram 2026-09-26 («Создай новую ветку для Phase 9, Market Discovery & Trend Intelligence. Проведи исследование и составь план. Приступай к выполнению плану.») — явная переприоритизация поверх §2a `docs/roadmap/FUTURE_PHASES.md` (Operational Validation Gate по умолчанию идёт раньше Phase 9; см. `FUTURE_PHASES.md` §12 «CURRENT NEXT PRIORITY» для точной формулировки этого исключения).
- **Ответственность:** новый модуль `src/lib/market-intelligence/` (contracts/schemas/services/adapters/index) владеет двумя новыми таблицами — `research_channels`/`research_evidence` (SCHEMA_MIGRATIONS v22) — вручную заполняемый watchlist каналов, которые оператор не обязательно владеет. **Структурно и мехнически отделён от `channels`/`videos`**, никогда не join'ится с ними — это первый раздел приложения, чья единственная цель — данные о НЕ своих каналах (AGENTS.md §F). `channelId` — настоящий YouTube channel id (`UC...`), а не сгенерированный UUID, по аналогии с `channels.id`; watchlist глобальный (не привязан к одному конкретному владеемому каналу).
- **Операции:** `addToWatchlist` (отклоняет дубликат `RESEARCH_CHANNEL_ALREADY_WATCHED`, никогда не создаёт вторую строку и не перезаписывает `reason` молча), `listWatchlist`, `getWatchlistEntry`, `removeFromWatchlist` (удаляет канал и всю evidence в одной транзакции; идемпотентно — удаление уже отсутствующего канала не ошибка, по образцу `localization`'s `removeTrackedLanguage`), `recordEvidence` (ручная запись публичного наблюдения), `listEvidence`, `fetchPublicSnapshot` (слайс 3 — единственное действие модуля, делающее реальный исходящий вызов YouTube). `createdVia` — SERVER-STAMPED через отдельный параметр `callOrigin` на месте вызова (тот же приём, что и `content-proposals`' `createContentProposal`), никогда не берётся из основного входа (строгая Zod-схема отклоняет попытку передать его через тело запроса).
- **Публичный снапшот (слайс 3):** `getPublicChannelSnapshot` (`src/lib/youtube-read-gateway/data-api.ts`, `channels.list` с `part=snippet,statistics`) — отдельная функция от `getChannelForSync` (та именована и предназначена для "своего" канала, не запрашивает `statistics`). `subscriberCount` становится `null`, когда `hiddenSubscriberCount === true`, чтобы не выдавать настоящий "0", который в этом случае возвращает YouTube, как достоверное наблюдение — то же правило "никогда не фабриковать значение", что уже применяется к `viewCount`/`commentCount`/`likeCount` в этом гейтвее. Наблюдение включает `title` (иначе оператор, добавивший канал по голому id, никогда не видел бы его настоящего названия) и текстовую оговорку, что `subscriberCount` — округлённое YouTube значение, а не точное. Записывается с `source: "youtube.channels.list"`, `confidence: "high"` (не `"confirmed"` — этот лейбл переоценивал бы точность округлённого показателя).
- **Явные ограничения объёма (владелец, `docs/roadmap/plans/PHASE_9_PLAN.md` §4):** ни автоматического обнаружения новых каналов, ни `search.list`, ни приватных аналитических полей (CTR/retention/revenue) для не своего канала, ни выводов о прибыльности/ранжировании — только сырые, подтверждённые источником наблюдения. Отдельно: никакого thumbnail (сознательно отложено — см. `docs/roadmap/plans/PHASE_9_PLAN.md` §4).
- **Механическая изоляция (не только документацией):** `write-path-inventory.test.ts` (по образцу `ai-connections`' одноимённого теста) доказывает (a) ни один файл модуля не ссылается на `write-context`/`assertWriteChannel`/`youtube-write-gateway`, (b) ни один файл вне `market-intelligence`'s собственного дерева не ссылается на его db.ts-символы напрямую (AGENTS.md §M: модуль должен быть независимо отключаемым) — включая его собственные API-маршруты и UI-панель, которые обязаны вызывать только экспортированное ядро модуля, а не `db.ts` напрямую. Список запрещённых символов **выводится динамически** из реального набора экспортов `db.ts` (а не поддерживается вручную) — независимое ревью (раунд 2, 2026-09-26) нашло, что первая версия ручного списка не включала только что добавленную `deleteResearchChannel`, и что allowlist-исключение для директории API-маршрутов было избыточно широким (реально не используется ни одним текущим файлом); обе находки исправлены в том же раунде.
- **API/UI:** `/api/market-intelligence/channels` (GET/POST), `.../[channelId]` (GET/DELETE), `.../[channelId]/evidence` (GET/POST), `.../[channelId]/fetch-public-snapshot` (POST) — все глобальные, без `channelId` в смысле «активный владеемый канал» (по образцу `/api/agent-connections`). Новая вкладка **Research** в дашборде (`src/components/market-research-panel.tsx`) — форма добавления в watchlist, кнопка «Remove» за `ConfirmDialog` (никогда `window.confirm`), форма ручной записи evidence, кнопка «Fetch public snapshot»; даты через `formatDisplayDateTime`.

- **Активность записи:** `listLatestUploadDates` (`MAX(published_at)` по сохранённым снимкам видео, в пределах 30 дней для API-данных) → `latestUploadPublishedAt`, `inactive` (дата известна и старше N месяцев; настройка `market_intelligence_inactive_after_months`, по умолчанию 6, Settings → API, `GET/POST /api/market-intelligence/inactivity`), `pausedAt`, `pausedReason`. Во всех чтениях списка: Research → Channels (колонка «Последний ролик», отметки паузы), `watchlist-table`, `query_competitors`, `query_market_overview`. Производной метрики по чужим данным нет (III.E.4.h).
- **Пауза (v74: `research_channels.paused_at`, `paused_reason`, `resumed_at`):** у записи на паузе свой статус сбора `paused` (не входит в «требуют внимания», есть в фильтре); она не собирается (`claimStaleResearchChannelsForCollection`, в том числе по одобренному запросу на сбор). Детектор (`evaluateInactivity` в `market-intelligence/services.ts`) работает в начале и в конце каждого прохода сбора: неактивная запись без паузы получает паузу `inactive` и одно ожидающее системное предложение `watchlist.delete` в одной транзакции (`pauseInactiveResearchChannel`); запись, которую владелец возобновил, когда она уже была неактивной, не ставится на паузу повторно за то же молчание (возобновление после посторонней паузы не защищает). Сбой детектора не останавливает сбор. Порог N хранится на каждом компьютере свой (RISK-121). Владелец ставит паузу и возобновляет в карточке записи (`POST /api/market-intelligence/channels/[channelId]/pause`); пишется только смена состояния.
- **Удалить полностью:** `deleteResearchChannel` теперь удаляет и связи записи с нашими каналами (`channel_record_assignments`), и её ожидающие предложения.
- **Предложения (`src/lib/agent-proposals/`, таблица `agent_proposals`, v74, в снимке передачи устройства, `notApiData`):** виды `watchlist.add|unfollow|pause|resume|delete`, `hypothesis.add`; одно наше `channelId` на предложение. Уникальный индекс по `dedupe_key`, который заполнен только у ожидающих (у решённых — NULL): pause/resume/delete — одно на запись (общий с системным), add/unfollow — на запись и канал.
