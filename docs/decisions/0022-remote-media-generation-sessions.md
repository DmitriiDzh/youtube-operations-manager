# 0022. Remote media generation: human-approved pod sessions, S3-only transport, per-device key file

Status: Accepted

**Date:** 2026-10-05. **Assigned by** the owner (Telegram, msgs 1471–1484): research, plan and
"Да, приступай к реализации". Research: `docs/roadmap/plans/MEDIA_GENERATION_RUNPOD_COMFYUI_SYNCTHING_RESEARCH.md`;
plan and acceptance criteria: `docs/roadmap/plans/PHASE_14_PLAN.md`.

## Context

The channel agent must be able to generate images, video and music on RunPod/ComfyUI through this product,
with models kept on the server only as long as needed and every result pulled to the machine running the
app. RunPod bills a *stopped* pod's disk at twice the running rate, a network volume at $0.07/GB/month, and
offers an S3-compatible API to that volume that works while no pod exists. ComfyUI has no authentication
and RunPod's HTTP proxy is public. Credentials must be entered in Settings and stored encrypted per device
(owner, msg 1480).

## Problem

How a session is authorised and paid for, how files travel, how the pod is secured, and where the secrets live.

## Alternatives

- **Syncthing on the pod** (the owner's first idea): push-based, but it needs a daemon and a TCP port per
  pod, an identity on the volume, and it cannot run while the pod is gone. Rejected once the owner accepted
  S3 (msgs 1476–1478): `/history` names the exact files, so pull is enough.
- **Serverless `worker-comfyui`**: cheaper for rare jobs, but each job pays a cold start, and an iterative
  session is what the agent does. Rejected for now; the S3 transport keeps it possible later.
- **Approval per job** (ADR 0021's shape): would block every iteration. Rejected (D3).
- **Env-var encryption key** (ADR 0008's shape): the owner asked for no `.env` step. Rejected (msg 1480).
- **Stop the pod when idle**: doubles the disk bill. Rejected: the only idle state is *terminated*.

## Decision

1. **Session = one pod, approved by a human (D2/D3).** The agent (or the operator) requests a session with
   `maxMinutes`/`maxUsd`; the estimate is `savedGpuPrice × minutes / 60`, computed locally. Approval is
   Web-only (`POST /api/media-generation/sessions/{id}/approve`, fenced from MCP/CLI by inventory test);
   preconditions run before any transition; the pod is created from a template with the network volume at
   `/workspace`, `8189/http` and a per-session `COMFY_TOKEN`; the route blocks until ComfyUI answers behind a
   Caddy bearer proxy (D6). A watcher terminates on idle / minutes / USD; boot sweep and shutdown hook make
   sure no pod outlives the process. `UNIQUE(open_slot)` = one open session per device.
2. **S3-only transport (D1).** Outputs are written by ComfyUI under `/workspace/exchange/<jobId>/`, pulled over
   RunPod's S3 API (hand-written SigV4, verified against the AWS test vectors), hashed twice, recorded in
   `media_exchange_files`, deleted from the volume, and registered in `creative_assets` with provenance.
   Models reach the volume through a CPU pod (`hf download`), never through a GPU pod.
3. **Outputs land in `<workspace>/99 Data Exchange/From YTM/media/<jobId>/` (D4)**, resolved by the new shared
   `src/lib/workspace-exchange/` module (extracted from research-export, AGENTS.md §M).
4. **Per-device key file.** `media_credentials` and each session's proxy token are AES-256-GCM-encrypted
   under `app-data/media-generation.key` (0600), generated by the app on first save; never an env var; a
   copied database reads as "not configured".
5. **Single gateway.** `src/lib/media-gateway/` (RunPod REST v2, S3, ComfyUI) is the only module that may
   reach a runpod.io host (inventory test); one "Media gateway" toggle and three traffic counters.
6. **Agent surface (Agent API 3.3.0, domain `media_generation`)**: list templates, request/get session, get
   limits, create/get/cancel job. Templates are operator-imported (D7); prompts are job parameters.

## Consequences

- RunPod REST v1 is not used (it retires 2026-11-15). The v2 list-wrapper keys are read from docs and
  confirmed by the live spike (RISK-105).
- The key file has no rotation/backup procedure (RISK-105); the two older env-key modules are unchanged.
- Jobs poll in-process; a server restart fails the in-flight job as interrupted (its pod is swept too).
- Serverless, concurrent sessions, YouTube upload of generated media and prompt libraries stay out of scope.

Purely additive: schema v50 (`media_credentials`), v51 (`media_sessions`), v52 (`media_workflow_templates`,
`media_jobs`, `media_exchange_files`), v53 (`media_sessions.stopping_outcome`, nullable), v54 (`media_sessions.last_seen_alive_at`, nullable), v55 (`media_workflow_templates.output_node_ids_json`/`node_count`, nullable), v56 (index `creative_assets_reference_idx`), all device-local; one more `app_settings` key (`media_volume_lock`, the session/pull mutual-exclusion row); three new `app_settings` keys; Agent API MINOR bump
3.2.0 → 3.3.0 (new tools only). No existing route, tool, table or contract changed.
